## 4. 开发原则
- 先跑通最小闭环：录入客户 -> 类型判断 -> 会前简报
- 先规则/检索，后生成：避免一开始就过度依赖 LLM
- 知识可追溯：建议必须能关联到知识库来源
- 现场可用优先：会前/会中场景优先于后台大报表

## 8. 测试与运行保障
- 固定重启脚本：`scripts/run_tests_with_restart.sh`，每次测试前会终止旧进程、初始化 SQLite、重启 backend/frontend、校验登录后跑 pytest
- 前端冒烟脚本：`scripts/frontend_smoke_test.py`，覆盖登录、会话、会前/会中/会后、来源卡、权限等关键路径
- 调试日志：backend 看 `/tmp/sales-backend.log`，frontend 看 `/tmp/sales-frontend.log`

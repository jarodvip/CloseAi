# 接口设计

## 1. 基础约定
- 协议：HTTP/1.1 / HTTP2
- 格式：JSON
- 统一返回结构：`code`、`message`、`data`、`trace_id`
- 鉴权：除登录外，业务接口需携带 `Authorization: Bearer <access_token>`
- 权限：管理员可维护知识库；普通销售可查看并使用客户与会话能力

## 2. 认证相关接口
- `POST /api/v1/auth/login`：登录获取 token
- `GET /api/v1/auth/me`：获取当前登录用户信息

## 3. 客户相关接口
- `POST /api/v1/customers`：创建客户
- `GET /api/v1/customers`：客户列表
- `GET /api/v1/customers/{customer_id}`：客户详情
- `PATCH /api/v1/customers/{customer_id}/type`：更新客户类型

## 4. 会前简报接口
- `POST /api/v1/customers/{customer_id}/briefing`：生成会前简报
- 输入：客户资料、当前阶段
- 输出：类型判断、切入句、推荐案例、潜在异议、下一步动作、`llm_text`

## 5. 会中辅助接口
- `POST /api/v1/customers/{customer_id}/assist`：获取会中辅助
- 输入：当前阶段、实时输入、客户画像
- 输出：阶段提示、话术建议、异议应答、`llm_text`

## 6. 会后跟进接口
- `POST /api/v1/customers/{customer_id}/followup`：生成会后跟进包
- 输入：会议摘要、决策、待办
- 输出：跟进话术、任务列表、知识更新建议、`llm_text`

## 7. 知识库接口
- `GET /api/v1/knowledge/customer-types`：客户类型列表
- `GET /api/v1/knowledge/cases`：案例检索
- `GET /api/v1/knowledge/scripts`：话术检索
- `GET /api/v1/knowledge/evidence`：证据检索
- `POST /api/v1/knowledge/cases`：新增案例，仅管理员
- `POST /api/v1/knowledge/scripts`：新增话术，仅管理员

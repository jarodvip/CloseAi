# 接口设计

## 1. 基础约定
- 协议：HTTP/1.1
- 格式：JSON
- 统一返回结构：`code`、`message`、`data`、`trace_id`
- 鉴权：除登录外，业务接口需携带 `Authorization: Bearer <access_token>`
- 权限：
  - `admin`：可访问全部接口，可管理知识库、Research
  - `user`：可管理自己的客户、会话、简报等
- 客户数据按 `owner_id` 隔离，非 owner 访问返回 404

## 2. 认证相关接口

### POST /api/v1/auth/login
登录获取 token。

**请求体**：`{ "username": "string", "password": "string" }`
**响应**：`{ "access_token": "string", "role": "string" }`

### GET /api/v1/auth/me
获取当前登录用户信息。

## 3. 客户相关接口

### GET /api/v1/customers
客户列表（当前用户可见）。

### POST /api/v1/customers
创建客户。

**请求体**：`CustomerIn`（name, industry, revenue_range, stage, region）
**响应**：`CustomerOut`

### GET /api/v1/customers/{customer_id}
客户详情。

### PATCH /api/v1/customers/{customer_id}/type
更新客户类型标注。

**请求体**：`{ "primary_type": "string", "secondary_type"?: "string", "type_confidence"?: number, "type_evidence"?: "string" }`

### POST /api/v1/analyze
快速分析客户信息并创建客户（自动推断类型）。

**请求体**：`{ name, industry?, revenue_range?, stage?, region? }`
**响应**：分析结果 + 创建的客户对象

## 4. 会前简报接口

### POST /api/v1/customers/{customer_id}/briefing
生成会前简报。

**查询参数**：`session_id?: int`（关联会话）
**响应**：`{ customer_name, likely_type, confidence, opening_line, focus, next_step, recommended_cases, potential_objections, source_refs, llm_text?, llm_source_cards? }`

### GET /api/v1/customers/{customer_id}/briefing-history
获取简报历史。

**查询参数**：`limit?: int`（默认 20）

## 5. 会中辅助接口

### POST /api/v1/customers/{customer_id}/assist
获取会中辅助建议。

**请求体**：`{ current_stage: string, transcript?: string, customer_type?: string }`
**响应**：`{ current_stage, tips, objections, suggested_reply, source_cards }`

## 6. 会后跟进接口

### POST /api/v1/customers/{customer_id}/followup
生成会后跟进包。

**请求体**：`{ summary?: string, decisions?: string[], pending_actions?: string[], transcript?: string, customer_type?: string }`
**响应**：`{ summary, decisions, actions, suggested_followup, knowledge_updates }`

## 7. 跟进记录接口

### POST /api/v1/customers/{customer_id}/interactions
创建跟进记录。

### GET /api/v1/customers/{customer_id}/interactions
获取跟进记录列表。

## 8. 会话/消息接口

### POST /api/v1/chat/sessions
创建会话。

**请求体**：`{ customer_id?: int, title?: string }`

### GET /api/v1/chat/sessions
获取会话列表。

**查询参数**：`customer_id?: int`

### PATCH /api/v1/chat/sessions/{session_id}
重命名会话。

### DELETE /api/v1/chat/sessions/{session_id}
删除会话（级联删除消息）。

### GET /api/v1/chat/sessions/{session_id}/messages
获取会话消息列表。

### POST /api/v1/chat/sessions/{session_id}/messages
发送消息并获取 AI 回复。

**请求体**：`{ role: "user"|"assistant", content: string }`
**响应**：`{ session_id, message, trace_id, source_cards[], source_refs[] }`

## 9. 知识库接口

### GET /api/v1/knowledge/customer-types
客户类型列表。

### GET /api/v1/knowledge/cases
案例检索。

**查询参数**：`query?: string`（模糊搜索）

### GET /api/v1/knowledge/scripts
话术列表。

### GET /api/v1/knowledge/evidence
数据证言列表。

### GET /api/v1/knowledge/options
获取前端选项（行业、阶段、场景、客户类型、决策、动作）。

### POST /api/v1/knowledge/cases
新增案例（仅 admin）。

### POST /api/v1/knowledge/scripts
新增话术（仅 admin）。

## 10. Research 外部数据接口

### GET /api/v1/research
检索外部数据块。

**查询参数**：`q?: string`（关键词）, `industry?: string`, `customer_id?: int`, `k?: int`（1-50，默认 5）**
**权限**：仅 admin

### POST /api/v1/research/import-url
抓取内网/外部页面并入库。

**请求体**：`{ url: string, industry?: string, source_name?: string }`
**权限**：仅 admin

### DELETE /api/v1/research/chunks/{chunk_id}
删除数据块（仅 admin）。

### POST /api/v1/customers/{customer_id}/research/refresh
为客户重新执行背调（联网检索并存库）。

## 11. Dashboard 接口

### GET /api/v1/dashboard/stats
获取看板统计数据。

**响应**：`{ total_customers, type_distribution[], total_briefings, total_interactions, followups_with_summary, briefing_trend[], stage_distribution[] }`

## 12. Feedback 来源卡反馈接口（v0.8）

### POST /api/v1/feedback
来源卡采纳/无效反馈。

**请求体**：`{ scene: "briefing|assist|followup|chat", rating: "up|down", source: string, label?: string, customer_id?: int, comment?: string }`
**权限**：登录用户

### GET /api/v1/feedback/stats
采纳率统计：总体采纳率 + 分场景（up/down/total/adoption_rate）+ 最近 20 条。

## 13. 知识沉淀建议审核接口（v0.8，仅 admin）

### GET /api/v1/knowledge/suggestions?status=pending
列出建议草稿（pending/approved/rejected）。

### POST /api/v1/knowledge/suggestions/{id}/approve
审核通过并入库。可选请求体编辑字段：`{ suggestion_type?, scene?, ktype?, title?, industry?, content?, note? }`。
入库去向：script → scripts 表；case → cases 表（自动生成编码）；evidence → evidence 表。响应含 `knowledge_id`。
已处理的建议返回 409。

### POST /api/v1/knowledge/suggestions/{id}/reject
驳回建议。请求体：`{ note?: string }`。

> 会后跟进响应中的 `knowledge_suggestions[]` 为自动生成的待审草稿（transcript 含"异议/预算"信号时生成 1 条话术沉淀建议）。

## 14. Dashboard 统计扩展（v0.8）
`GET /api/v1/dashboard/stats` 响应新增：
- `feedback`：`{ total, up, down, adoption_rate, by_scene[], recent[] }`
- `llm`：近7天 `{ total, success, degraded, success_rate, degrade_rate, total_tokens, avg_latency_ms, by_scene[] }`

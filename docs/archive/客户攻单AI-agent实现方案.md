# 客户攻单AI：Agent 实现方案

> **⚠️ 本文档已过时 — 反映立项初期的技术方案，与实际架构不符。**
> 当前项目状态见 [`README.md`](README.md)。

## 1. 先明确：这个 Agent 要做什么
### 1.1 核心价值
- 不是替代销售，而是把“经验判断、资料检索、话术组合、下一步动作”系统化。
- 核心循环：
  - 见客户前：自动判断客户类型，生成战前卡片
  - 会中：实时提醒话术、异议应答、案例引用
  - 会后：生成跟进包、更新客户画像、沉淀可复用素材

### 1.2 与普通聊天机器人的本质区别
- 普通问答：一问一答，不控流程，不接工具，不复盘
- Agent：有目标、会拆步骤、能调工具、能读写上下文、能把结果落回业务系统

## 2. Agent 架构设计
### 2.1 四层架构
```
用户/销售
   ↓
对话层（前端/企微/飞书/电话系统）
   ↓
Agent 核心层（记忆 + 规划 + 工具 + 行动）
   ↓
数据层（知识库 + CRM + 会话记录 + 案例库）
```

### 2.2 Agent 核心模块
1. **记忆模块**
   - 短期记忆：当前客户会话、会中实时笔记
   - 长期记忆：客户类型标签、历史攻单策略、案例使用记录
   - 知识记忆：7类客户画像、五步法、案例库、数据证言

2. **规划模块**
   - 任务分解：把“准备一次客户拜访”拆成信息收集 → 类型判断 → 策略匹配 → 话术生成 → 材料准备
   - 会话阶段控制：严格按五步法推进，不跳步
   - 异常处理：客户拒绝、决策人变化、预算不足等分支处理

3. **工具模块**
   - 客户分析工具：读取客户资料、官网、融资新闻、行业报告
   - 知识检索工具：从结构化知识库中检索案例、话术、数据证言
   - 生成工具：生成会前简报、会中提示、会后跟进话术
   - 外部工具：CRM 读写、邮件发送、日程预约、录音转写

4. **行动模块**
   - 输出结构化结果，而不是只输出聊天文本
   - 可执行动作：创建跟进任务、更新客户标签、发送邮件草稿
   - 可审计日志：记录每次建议的依据，方便复盘和优化

## 3. 数据层设计
### 3.1 知识库结构（基于两份PPT提炼）
```yaml
客户类型知识库:
  - 品牌野心型
  - 定位卡位型
  - 品类开创者型
  - 竞争突围型
  - 资本叙事型
  - 全国化扩张型
  - 品牌焕新型

每个类型包含:
  - 识别信号
  - 核心痛点
  - 攻单策略
  - 核心话术
  - 禁忌
  - 典型案例
  - 推荐数据证言

攻单流程库:
  - 听: 辨类问诊 checklist
  - 认: 点破处境模板
  - 比: 案例匹配规则
  - 算: 价值量化方法
  - 定: 锚定行动模板

案例库:
  - 行业、阶段、规模、困境、动作、结果、指标、金句

话术库:
  - 破冰话术
  - 异议应答
  - 跟进模板
```

### 3.2 业务数据
- 客户资料：公司名、行业、规模、融资阶段、竞品、历史投放
- 会话记录：通话/会议转写、微信记录、邮件往来
- 跟进记录：下次动作、待决策问题、关键决策人
- 效果数据：方案通过率、转化周期、案例复用率

## 4. 实现路径：从规则型 Agent 到智能型 Agent
### 阶段一：工作流 Agent（1-2周）
- 用确定性流程实现，不依赖复杂LLM推理
- 核心能力：
  - 客户资料输入 → 规则匹配 → 输出客户类型标签
  - 按五步法生成标准化会前/会中/会后模板
  - 基于知识库检索输出话术和案例
- 优势：稳定、可控、容易调试，适合MVP验证

### 阶段二：LLM 增强 Agent（3-4周）
- 引入 LLM 做自然语言理解和生成
- 核心能力：
  - 客户资料自动摘要和信号提取
  - 会前简报自动生成
  - 会中实时话术推荐（基于会话上下文）
  - 会后跟进话术自动生成
- 关键：LLM 只负责理解和生成，业务规则仍由结构化知识库控制

### 阶段三：自主规划 Agent（5-8周）
- Agent 能自主判断当前处于哪个阶段，主动推进
- 核心能力：
  - 自主规划拜访策略
  - 多轮会话中持续跟踪目标完成度
  - 自动识别客户类型变化
  - 建议最佳下一步动作
- 关键：加入明确的阶段判断和目标追踪机制

## 5. 具体功能设计
### 5.1 会前准备 Agent
```
输入：客户公司名/官网/行业/规模/当前阶段
处理：
  1. 信息收集：自动抓取公开信息（融资新闻、行业报告、竞品动态）
  2. 信号提取：识别客户类型信号词（长期主义/估值/全国化/年轻化等）
  3. 类型判断：结合规则 + LLM 判断主类型和次类型
  4. 策略匹配：匹配对应的攻单策略和案例
  5. 材料生成：会前简报、破冰话术、潜在异议、推荐案例
输出：结构化会前卡片
```

### 5.2 会中辅助 Agent
```
输入：实时语音/文字输入 + 客户画像 + 阶段标签
处理：
  1. 实时转写：语音转文字（可选）
  2. 信号识别：识别客户是否提到新信号、新 objection
  3. 话术推荐：根据当前阶段推荐下一步话术
  4. 案例引用：推荐最相关的案例片段
  5. 笔记摘要：实时生成结构化笔记
输出：实时提示 + 会话摘要
```

### 5.3 会后跟进 Agent
```
输入：会话记录/转写 + 客户类型 + 会议要点
处理：
  1. 摘要生成：总结会议核心结论
  2. 类型确认：确认或修正客户类型标签
  3. 下一步动作：生成具体跟进任务（3城1月测试/对接关键人）
  4. 话术生成：生成跟进邮件/微信/SOP
  5. 知识沉淀：提取可复用的新话术或新案例
输出：跟进包 + 更新后的客户画像
```

## 6. 技术选型建议
### 6.1 快速启动方案
- LLM：GPT-4o / Claude 3.5 Sonnet / 国内可用的大模型 API
- 知识检索：简单关键词匹配 + 规则引擎（MVP阶段）
- 前端：Streamlit / Chainlit / 飞书多维表格 / 企业微信小程序
- 后端：Python FastAPI / Node.js
- 数据库：PostgreSQL（业务数据） + JSON/CSV（知识库，MVP阶段）

### 6.2 生产化方案
- LLM：GPT-4o / Claude 3.5 Sonnet / 通义千问 / 文心一言
- 知识检索：向量数据库（Pinecone / Milvus / Chroma）+ 混合检索
- 工作流：LangGraph / CrewAI / 自研状态机
- 前端：Web App + 企微/飞书嵌入
- 后端：FastAPI + 任务队列
- 数据库：PostgreSQL + Redis + 向量数据库
- 监控：LLM 调用日志、建议采纳率、转化周期追踪

## 7. 最小可行 Agent（MVP）
### 7.1 范围
- 支持1个销售角色（如客户经理）
- 支持3类客户类型（如品牌野心型、竞争突围型、全国化扩张型）
- 覆盖会前准备 + 会中辅助 + 会后跟进
- 不接CRM，用Excel/飞书表格管理客户数据

### 7.2 核心流程
1. 销售输入客户资料
2. Agent 自动判断客户类型
3. 生成会前简报（1页A4）
4. 会中实时推荐话术（手机/电脑端）
5. 会后生成跟进话术和下一步动作

### 7.3 验证指标
- 会前准备时间：从30分钟缩短到5分钟
- 首面破冰成功率：客户愿意深入交流的比例
- 方案通过率：进入下一轮的比例
- 销售满意度：是否愿意继续使用

## 8. 关键挑战与解决
### 8.1 幻觉问题
- 解决：LLM 生成内容必须标注知识库来源，关键数字必须来自知识库
- 解决：建立事实核查层，客户类型判断必须有明确的信号依据

### 8.2 销售习惯改变
- 解决：先做“增强”而不是“替代”，让销售感受到效率提升
- 解决：每周复盘 Agent 建议的采纳率和效果，持续优化

### 8.3 知识库维护
- 解决：建立“销售-运营-技术”三方维护机制
- 解决：每次成功/失败案例都沉淀为可复用的结构化数据

### 8.4 数据安全
- 解决：客户资料脱敏处理
- 解决：分权限访问（销售/主管/管理员）
- 解决：所有操作留痕，可审计

# 外部数据层设计

> 状态：已评审通过（2026-08-27）。目标：为会前背调、行业分析、会中助手、方案生成提供统一的外部数据底座。

## 1. 背景与目标

MVP 已完成客户录入 → 类型判断 → 会前简报 → 会中助手闭环，但 LLM 只靠参数知识回答，存在"空谈"问题。本迭代补齐外部数据源：

| 场景 | 数据需求 |
|---|---|
| 会前简报·客户背调 | 目标公司业务规模、近期动态、广告投放情况 |
| 行业市场数据 | 行业规模、竞争格局、人群触达等公开报告内容 |
| 会中助手 RAG | 对话时实时检索补充依据 |
| 方案生成打底 | 为后续 fm-pipeline 全链路接入准备数据层 |

**技术路线（已选定）：轻量数据层。** 不引入向量库等新基础设施，SQLite FTS5 全文检索 + 统一文本块表；预留 embedding 列支持二期平滑升级。

## 2. 数据来源与约束

- **模型自带联网**：内部 LLM API 具备联网能力，用于客户背调
- **内部存量数据**：PDF/Word 行业报告 + 内网页面，需解析入库
- **第三方搜索兜底**：本期不接。模型联网不够用时再选型（候选：博查 / Tavily）
- **待确认**：
  - [ ] 内部模型联网能力的具体调用方式（请求参数/计费）→ 在拿到文档前先做适配层 + 普通生成兜底
  - [ ] 存量 PDF/Word 样本与数量 → 导入脚本按容错设计（单文件失败不中断批量）

## 3. 数据模型

新增 `ResearchChunk` 表（`app/models/research.py`），现有 4 张知识表不动：

```python
class ResearchChunk(Base):
    id = Column(Integer, primary_key=True, index=True)
    source_type = Column(String(20), nullable=False)   # doc / web / research
    title = Column(String(200), nullable=True)
    url = Column(String(500), nullable=True)
    source_name = Column(String(100), nullable=True)
    industry = Column(String(100), nullable=True)      # 行业标签，检索过滤
    customer_id = Column(Integer, nullable=True, index=True)  # 背调结果挂具体客户
    content = Column(Text, nullable=False)
    chunk_index = Column(Integer, default=0)
    fetched_at = Column(DateTime, nullable=True)
    created_at = Column(DateTime, default=datetime.utcnow)
    embedding = Column("embedding", LargeBinary, nullable=True)  # 预留，二期
```

追溯原则：每个文本块必须能回答"从哪来"（source_type + url/source_name）和"何时来"（fetched_at）。

## 4. 摄取管道

三个入口，统一走同一个分块入库函数 `ingest_chunks()`：

### 4.1 存量文档导入
`scripts/import_docs.py`：
- pypdf 解析 PDF、python-docx 解析 Word
- 按段落聚合 ~500 字分块
- 支持目录批量导入；单文件解析失败记录日志并继续
- 命令行：`python scripts/import_docs.py <目录或文件> --industry <行业> --source-name <名称>`

### 4.2 内网页面抓取
`POST /api/v1/research/import-url`：
- 后端 httpx 抓取 + readability-lxml 提正文
- 分块入库，source_type=web
- 仅 admin 可调用

### 4.3 联网背调
`llm_service.call_llm_with_search(prompt)` 适配层：
- 内部 API 联网能力就绪前，降级为普通 chat completions（在提示词中声明信息可能过期）
- 背调报告生成后存 research_chunks（source_type=research，挂 customer_id）

## 5. 检索层

- SQLite FTS5 虚表 `research_chunks_fts`（content/title/industry/customer_id 列）
- jieba 预分词：写库时分词后入索引（Python 层处理，不用自定义 tokenizer 扩展）
- knowledge_service 新增：

```python
def search_research(db, query: str, industry: str = None,
                    customer_id: str = None, k: int = 5) -> list[ResearchChunk]
```

返回带完整来源元数据的文本块，供上层标注引用。

## 6. 业务集成点

| 服务 | 集成方式 |
|---|---|
| briefing_service | 简报生成前按行业+客户检索 top-k 注入"外部情报"区块，来源卡展示 |
| chat_service / assist_service | 收到提问先 search_research 取 top-k，注入系统上下文后再回答，回答附来源 |
| analysis_service | 类型判断结论可引用行业数据佐证 |

降级策略：检索无命中时行为不变（不注入、不编造），保持现有流程可用。

## 7. 新增 API（`/api/v1/research`）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/research?q=&industry=&customer_id=` | 检索调试与列表 | 登录用户 |
| POST | `/research/import-url` | 抓取内网页面入库 | admin |
| DELETE | `/research/chunks/{id}` | 删除文本块 | admin |
| POST | `/customers/{id}/research/refresh` | 触发指定客户联网背调刷新 | 登录用户（仅本人客户） |

沿用现有数据归属隔离规则。

## 8. 依赖清单

pypdf、python-docx、readability-lxml、jieba（均纯 Python 库，无服务端依赖）
